Build a production-ready **Custom Quiz/Reviewer System** for a real client. This is NOT a demo and NOT a generic mockup. Follow the requirements below exactly. Do not remove, simplify, replace, or add major functionality without asking first.

## PROJECT

**Project Type:** Custom Web-Based Quiz/Reviewer System

**Purpose:**  
Create a mobile-friendly reviewer and quiz platform where an administrator manages students, subjects, enrollments, questionnaires, question banks, attempts, and results. Students have individual accounts and can access only the subjects in which they are enrolled.

This is primarily a REVIEWER system, so students may take questionnaires repeatedly depending on the attempt settings.

## SUBJECT ENROLLMENT & ACCESS CONTROL

Admin must be able to assign each student to one or multiple subjects.

This access control is mandatory.

Example:

If Student A is enrolled only in Mathematics:
- Student A can see Mathematics.
- Student A can access published Mathematics reviewers.
- Student A CANNOT access English, Science, or their questionnaires unless enrolled in those subjects.

Do not rely only on hiding UI elements. Enforce this access at the backend/database authorization level as well.

## QUESTION BANK

Build a reusable question-bank system.

Admin must be able to:
- create questions
- edit questions
- delete questions
- organize questions
- associate questions with subjects
- reuse questions in different reviewer sets
- search/filter questions where useful
- bulk import questions

The architecture must be suitable for a large question bank.

Expected usage may reach approximately:
- 100–300 reviewer/questionnaire sets
- around 100 questions per set
- potentially around 30,000 stored questions overall

Do NOT hard-code these numbers as limits.

Use pagination/server-side querying where appropriate. Do not load the entire question bank into the browser unnecessarily.

## QUESTION TYPES

The system must NOT be limited to multiple-choice questions.

Support at minimum:

### 1. Multiple Choice — Single Answer
- Admin creates multiple choices.
- One correct answer.
- Automatically scoreable.

### 2. Choose All That Apply / Multiple Answers
- Multiple choices.
- More than one answer can be correct.
- Student may select multiple answers.
- Automatically scoreable according to the defined correct-answer set.

### 3. Fill in the Blank
- Student types an answer.
- Admin can define the correct answer.
- Allow multiple accepted answer variations where appropriate.
- Normalize reasonable differences such as surrounding spaces/capitalization unless the quiz setting requires otherwise.

### 4. Short Answer / Text Box
- Student enters a short text response.
- Can be automatically checked only when the admin has provided defined accepted answers.
- Otherwise allow admin/manual checking.

### 5. Long Answer / Paragraph
- Student can enter a longer response.
- Allow admin/manual checking/scoring.

### 6. Multiple Typed Answers / Multiple Blanks
Support a question that requires more than one typed answer.

Example:
Question contains three required blanks/answer fields.

Store and evaluate each required answer appropriately.

Admin must be able to create a reviewer containing a specific fixed set of questions.

## RANDOM QUESTION SELECTION

Admin must also have the option to create a reviewer from a larger question bank.

Example:

Mathematics question bank = 1,000 questions.

Admin configures reviewer:
"Questions per attempt: 100"

The system randomly selects 100 eligible questions for the attempt.

Make this configurable ON/OFF.

The system must support BOTH:
- fixed questionnaires
- randomized questionnaires

Do not force randomization.

## QUESTION / CHOICE RANDOMIZATION

Where appropriate, provide settings for:
- randomizing question order
- randomizing answer-choice order

These should be configurable rather than permanently enabled.

Ensure randomizing choices does not break correct-answer tracking.

## QUIZ EXPERIENCE

Display **ONE QUESTION AT A TIME**.

The interface must work well on:
- phones
- tablets
- laptops
- desktops

Provide clear navigation/progress such as:
- current question number
- total questions
- next/previous controls where allowed
- submission state

Prevent accidental loss of an active attempt where reasonably possible.

## ATTEMPT SETTINGS

Admin can configure:
- specific number of attempts
OR
- unlimited attempts

Track attempts separately.

Each attempt must preserve the questions/answers needed for accurate historical review, particularly when randomized question selection is used.

## INSTANT ANSWER FEEDBACK

Provide an admin-configurable ON/OFF setting.

### ON
After the student answers a question, the system may show:
- correct/incorrect
- correct answer where appropriate

Then the student continues.

### OFF
Do not reveal correctness immediately.

Student continues through the questionnaire and receives results/review according to the final settings.

## UNANSWERED QUESTIONS

Provide an admin-configurable submission setting.

### Require All Answers = ON
Student cannot submit while required questions remain unanswered.

Clearly notify the student that unanswered questions remain.

### Require All Answers = OFF
Student may submit with unanswered questions.

Store those questions as unanswered and score them appropriately.

## SCORING

Automatically score objective questions where a correct answer can be reliably defined.

Examples:
- multiple choice
- choose all that apply
- defined fill-in answers
- defined short answers

Do NOT use AI grading.

For free-text/paragraph responses that cannot be objectively scored:
- mark them as requiring admin review/manual checking
- allow admin to assign/update the score where appropriate
- ensure final score/status can correctly reflect pending manual review if necessary

Do not incorrectly mark subjective answers wrong simply because automatic scoring is unavailable.

## RESULTS

## ANSWER REVIEW

- question

- correct answer
- correct/incorrect status

Do not expose correct answers when the applicable reviewer settings say they should remain hidden.

7. Define bulk-import format.
8. Only then begin implementation.

## PRIMARY GOAL

The finished system must make it FAST for the administrator to manage a large reviewer library while keeping student access controlled.

The client should be able to:

CREATE/IMPORT STUDENTS → CREATE SUBJECTS → ENROLL STUDENTS → CREATE/IMPORT QUESTIONS → BUILD FIXED OR RANDOMIZED REVIEWERS → PUBLISH → STUDENTS TAKE REVIEWERS → AUTOMATICALLY SCORE APPLICABLE QUESTIONS → MANUALLY REVIEW SUBJECTIVE ANSWERS → VIEW/EXPORT RESULTS.

The student experience should be:

LOGIN → SEE ONLY ENROLLED SUBJECTS → CHOOSE REVIEWER → TAKE ONE QUESTION AT A TIME → SUBMIT → RECEIVE RESULT/FEEDBACK ACCORDING TO SETTINGS → REVIEW ATTEMPT IF ALLOWED.

Build exactly around this workflow.
